## P1.1 — `eigentt:TypeExpr` → `eigentt:Term`

Renamed: the class IRI (`urn:eigenius:eigentt:TypeExpr`), its short form in prose, its
`core:short_name`, and the three `ValidationRule` variants named after it
(`TypeExprMalformed` / `TypeExprIllTyped` / `TypeExprNotAProposition` →
`TermMalformed` / `TermIllTyped` / `TermNotAProposition`). 130 IRI sites across 27 files.
The 20 constructors are unchanged.

**Two things named `TypeExpr` were deliberately left alone, and neither is the class.**

- **The ESL surface keyword `type_expr( … )`.** It is matched literally by the parser and is
  not derived from the class name. It sits on **2,641,933** committed `lexicon:cat` values and
  **2,641,933** `lexicon:sem_type` values (P0.1), plus every authored artifact. Renaming it is
  a chain-wide edit with no bearing on the class's identity, and the plan scopes P1's rename to
  "51 ontology sites, 21 Rust files" — three orders of magnitude below that. **Open question,
  not a decision**: the keyword now constructs an `eigentt:Term`, so the surface and the class
  disagree by name. Settling it is a reseed-scale edit and belongs with one that is already
  happening.
- **`ast::TypeExpr` (`kernel/src/esl/ast.rs:550`).** A separate, restricted ESL grammar node —
  its own doc says *"Purposely restricted — this isn't a full type-expression grammar, just
  enough for the codata observation-type surface."* Unrelated to the class; 78 of the raw
  `TypeExpr` matches are this. Renaming it would have been a false positive.

## P1.2 — `eigentt:Judgement` and `eigentt:Logic`

Declared in `ontologies/eigentt/eigentt-type-fragment.json` — bootstrap layer 2, directly above
`core`, which is where they can see `eigentt:Term` and where nothing below them needs to see
them.

```
data eigentt:Logic     { kernel, lean4 }
data eigentt:Judgement { holds(logic : Logic, term : Term, type : Term) }
```

**`Logic` is a closed inductive, and `reflection:proof_system` is an open string. That is not an
inconsistency.** `proof_system` records which verifier ran and its own description says
*"Illustrative, not an allows_only: adding a verifier must not be a bootstrap edit."* An
inhabitant of `eigentt:Logic` asserts something stronger — that the system **hosts a checker**
for that logic's proof language, which admits the checker to the trusted computing base and
requires the two arguments the paper names. That should be a bootstrap edit. The two carry
different claims, so they are typed differently.

**Nothing ranges over `Judgement` yet.** P2 introduces the uniform check-mode rule that consumes
it. P1 adds the declaration only, so validation behaviour is unchanged.

## P1.3 — the `justification:` namespace

25 declarations moved from `urn:eigenius:reasoning` to `urn:eigenius:justification`, per the
plan's table. `JustificationTerm → Term`, `JustifiedBy → Certificate`,
`ReasoningSentence → Sentence`, `JustificationProjection → Projection`,
`reasoning:justification → justification:term`; the rest keep their local names.

**Grounding constructors renamed**: `DeclaredEvidence → Declared`, `ObservedEvidence → Observed`,
`VerifiedEvidence → Verified`. `DerivedEvidence` keeps its name — P4 deletes it, so renaming it
here would be a rename inside a deletion. The predicted consequence landed:
`Ground::from_ctor` (`project.rs:79`) now matches `"Declared" → Ground::Declared` directly and
translates only the one constructor that is on its way out.

**The institution resources keep the `reasoning:` prefix**, as the plan specifies — the
institution, `ef_justification`, the four QueryClasses and the `proc:*` handles, 13 sites. They
leave with P7. **Exit criterion met**: no `urn:eigenius:reasoning:` IRI names a class, property
or inductive.

### `witness:` landed at `urn:eigenius:witness`

The plan requires the ChainWitness namespace to leave `urn:eigenius:reasoning:ChainWitness` at
P1 and to land at its P7 destination directly rather than parking under `justification:`. P7
says that destination is "kernel base vocabulary"; no such namespace existed, so this phase
chose one.

`urn:eigenius:witness` was taken because **the short form `witness:` does not change**. All 16
use sites keep their bodies verbatim; only the namespace declaration line moves. The four
well-known constants now read `urn:eigenius:witness:IsDeclaredAs` and so on, and the two
recognition paths stay consistent — `chain_witness_category_for_iri` matches the full IRIs,
`check_hooks.rs` matches the unchanged short names.

The **declaration site** does not move here. P7 moves it into the kernel; P1 moved the IRI only.

### The ontology file was renamed too — beyond the plan's text

`ontologies/reasoning/reasoning.esl` → `ontologies/justification/justification.esl`, and the
bootstrap layer name `reasoning` → `justification`.

The plan says to move the declarations and does not mention the file. Renaming it now was chosen
because the file otherwise declares 25 `justification:*` things and 7 `reasoning:*` things while
being named for the minority — the exact naming sediment P1.3 exists to remove — and because the
bootstrap layer name is derived from it, so deferring means moving the layer identity twice and
paying two manifest rewrites instead of one.

**This makes one line of the plan stale.** P7's removal inventory pins
*"`kernel/src/esl/compile.rs:6223-6244` asserts `reasoning.esl` contains the ExportFormat and the
QueryClasses"*. The assertions are intact and still pin those IRIs; the file they read is now
`justification.esl`.

**One class of failure the mechanical rename did not reach: inline ESL inside string literals.**
`justifiedby_type_writable.rs` builds two probe layers from ESL held in a Rust `r#"…"#`, and the
notebook holds a cell the same way. The namespace-declaration pass ran over `*.esl` only, so those
three bodies were rewritten to `justification:` while their headers still declared `reasoning`.
Caught by the suite (`unknown namespace alias: 'justification'`), not by any grep. Worth carrying
into P2 onward: **a rename is not done when the `.esl` files are done.**

The last two did not run: bootstrap had already drifted past every snapshot on disk.

**`experiments/parsing/baseline.json` remains the comparison target — no new baseline is needed.**
Namespaces and type names do not enter the parsing process, verified two ways:

- **`kernel/src/dcg/` contains zero references to anything P1 renamed.** The sole `eigentt:Term`
  occurrence is a doc comment (`lexicon.rs:27`). The parser reads `lexicon:*` slots; `class_types
  eigentt:Term` is a commit-time constraint that the parse path never consults, and
  `justification:*` / `witness:*` appear in it 0 times.
- **The recorded ranks replay.** `experiments/parsing/ranks/2026-07-29-demonstratives.json` keys its
  62 draws on sentence text, word surfaces and `wn:` / `umls:` sense IDs — none of which P1 touched.
  So the draws hit and the gate needs no live LLM calls.

**What still blocks a gate RUN is the fail-closed manifest hash, not baseline drift.** A store has
to be reseeded at the current bootstrap before the gate can open one. P2 is itself a bootstrap edit,
so the reseed belongs after P2's edits rather than between the two phases — and attribution stays
safe, because P1's independence from the parse path is measured above rather than assumed.

## Carried into P2 — the sentence class

An amendment arrived during P1 replacing `justification:Sentence` with a one-judgement class. It is
folded into the plan as [*Disposition: the sentence class*](judgements-warrants-build-plan.md).
Two things were settled here rather than left for P2:

**Its open check is answered, favourably.** The amendment flagged
`witness_index.rs`'s proposition hashing as the one place to verify before treating the collapse as
settled. `hash_stored_proposition` does **not** hash the stored JSON — it runs `decode_type` to an
`Exp` and hashes that. The emit side is already decode-then-hash, so the collapse changes where the
`Exp` is read from, not what is hashed, and the α/δ agreement pinned by
`emit_and_check_sides_agree_on_the_hash` is stated over `Exp` either way. The new obligation is the
projection step — recognising `Certificate(j, P)` in the judgement's type and taking `P` — which
needs its own test or the two sides drift silently and a `Verified` witness merely fails to appear.

Two readers take the proposition alone: `witness_index.rs:264` (above) and `entailment.rs:73`
(P7 deletes the file). `validate.rs:65-66` reads the pair, as the collapse assumes.

**Its counts were re-measured and corrected in the plan.** The amendment's figures were taken on the
pre-P1 names, and P1's prose rename inflated the denominators. Measured against
`: justification:Sentence {` declarations: **42 authored resources and 131 slot writes**, not 91;
6 fixtures; and `refutes` has **zero** authored uses, so it survives on its design argument alone.
`0` Rust sites construct a sentence, confirming the amendment's central premise.
